# Semantic Review (v1) - Portfolio Redesign

## Summary

Complete rewrite of a single-file inline HTML portfolio into a modular React SPA with 10 components, Framer Motion animations, dark/light mode, and responsive navigation. The architecture is clean with consistent component separation, shared accessibility patterns, and proper reduced-motion handling. However, the deployment story has a gap that will prevent GitHub Pages from serving the built site without additional CI configuration.

## Issues (4)

### 1. GitHub Pages deployment gap (CRITICAL)

No GitHub Action or build step copies `dist/` into the served directory. The root `index.html` references `/src/main.tsx` directly (Vite dev-mode entry point). Visiting the live site will fail to resolve the script.

**Fix**: Add a GitHub Actions workflow (`.github/workflows/deploy.yml`) that runs `npm run build` and publishes the `dist/` folder using `actions/deploy-pages` or `peaceiris/actions-gh-pages`.

### 2. Dark mode class vs. prop duality (MODERATE)

Tailwind `darkMode: 'class'` is configured but the `dark:` prefix is never used in component code. All theme branching happens through `darkMode` prop ternaries in every component. This creates unnecessary prop drilling and inflates components.

**Fix**: This is acceptable for now as refactoring to context + dark: utilities would be a larger change. But at minimum, remove the unused `darkMode: 'class'` from tailwind.config.js if not using dark: utilities, OR switch a few key ternaries to use dark: utilities to validate the pattern.

### 3. Project links point to profile (MINOR)

Two of three project cards link their "Code" button to `https://github.com/AARYANSHARMA19` (the profile page), not actual repositories. Users clicking through get a profile page, not project source.

**Fix**: Remove the "Code" link for projects that don't have a public repository, or change to a descriptive tooltip explaining the project is private/in-progress.

### 4. Hero gradient animation asymmetry (MINOR)

The `animate-gradient` CSS keyframe on background blobs is killed by the CSS media query but not gated by the `useReducedMotion` hook. Inconsistent with the JS-first pattern used elsewhere.

**Fix**: Minor inconsistency. The CSS media query handles it. No action strictly required, but for consistency could add a conditional class.

## Verdict

Issues 1 and 3 should be fixed. Issue 2 is acceptable as-is (prop-based approach works fine for a portfolio). Issue 4 is cosmetic.
