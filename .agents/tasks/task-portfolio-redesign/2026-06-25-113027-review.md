# React + Vite + Tailwind portfolio rebuild

Complete rewrite of a single-file inline HTML portfolio into a modular React SPA with 10 components, Framer Motion animations, dark/light mode, and responsive navigation. The architecture is clean — consistent component separation, shared accessibility patterns, proper reduced-motion handling — but the deployment story has a gap that will prevent GitHub Pages from serving the built site without additional CI configuration.

**Watch for:** GitHub Pages deployment gap (confirmed) — the build outputs to `dist/` but no GitHub Action or config tells Pages to serve from there. Dark mode class strategy mismatch between Tailwind config and runtime application (confirmed). Two project GitHub links point to the profile page rather than actual repositories (confirmed).

## High-level view

Dark mode uses a dual strategy that doesn't align: Tailwind is configured with `darkMode: 'class'` but the runtime toggles `.dark` / `.light` classes on the document root and checks `darkMode` prop booleans inline everywhere. The Tailwind `dark:` variant is never used in component code, so the config setting is dead weight, and the inline ternaries make components noisier than they need to be.

Deployment needs attention: the `README` documents building to `dist/` and says "configure GitHub Pages to serve from the `dist/` folder," but for a `username.github.io` repo GitHub Pages defaults to serving from root or `/docs` — there's no `.github/workflows` or `dist` checked in, so the live site will show the Vite dev `index.html` (which references `/src/main.tsx` — a path that won't resolve in production).

The animation layer is consistent and well-handled. The `useReducedMotion` hook listens for runtime changes to the OS media query, and the CSS layer independently kills all CSS-driven animations. One minor asymmetry exists in the Hero gradient blobs which rely solely on the CSS kill-switch rather than the JS hook.

Two of three project cards link their "Code" button to the GitHub profile URL, not an actual repository — users clicking through get a profile page, not project source.

## GitHub Pages deployment mismatch

The Vite config writes production output to `dist/`. For a `username.github.io` repository, GitHub Pages serves either from the repo root or a `/docs` folder — there's no native option to serve from `dist/`. The root `index.html` that currently exists references `/src/main.tsx` directly, which is a Vite dev-mode entry point. Visiting the live site today would load that HTML and fail to resolve the script.

Two paths forward: add a GitHub Actions workflow that runs `npm run build` and publishes the `dist/` folder (the `actions/deploy-pages` or `peaceiris/actions-gh-pages` patterns work here), or change `outDir` in `vite.config.ts` to `docs`, check it in, and point Pages at `/docs`. The workflow approach is cleaner since it avoids committing build artifacts.

## Dark mode architecture

`App.tsx` maintains a `darkMode` boolean in state, persists it to `localStorage`, and toggles `dark`/`light` classes on `<html>`. Every component receives `darkMode` as a prop and uses ternary expressions to swap class strings:

```tsx
className={`text-sm ${darkMode ? 'text-gray-400' : 'text-gray-500'}`}
```

Meanwhile, `tailwind.config.js` sets `darkMode: 'class'`, which enables Tailwind's `dark:` prefix — but this prefix appears nowhere in component code. The CSS in `index.css` uses `.dark body` and `.light body` selectors, but these only set background and text color at the body level. The result is two parallel theme systems: one via Tailwind's class strategy (unused in components) and one via explicit prop threading (used everywhere).

This inflates every component with conditional class logic that could be a single `dark:text-gray-400 text-gray-500` utility. Choosing one approach would reduce line count by roughly 30% per component and make the theme system easier to extend. As a secondary consequence, `darkMode` is prop-drilled through 10 components — a React context would eliminate the threading without adding meaningful complexity.

## Animation reduced-motion gap

The Hero section's background gradient blobs (`absolute ... blur-3xl`) have their parent `div` with no motion gating, and the `animate-gradient` class applies an infinite CSS keyframe. The CSS media query at the bottom of `index.css` forces `animation-duration: 0.01ms !important` when the OS prefers reduced motion, so in practice the animation is killed. But this is the only animation in the codebase that doesn't also have a JS-level gate via `useReducedMotion`. If the CSS rule were modified or overridden, reduced-motion users would see persistent background animation.

## Project content accuracy

The "GPU-Accelerated ML Pipeline" and "Java Microservices Training Project" cards both set their `github` link to `https://github.com/AARYANSHARMA19` — the user's profile page, not an actual repository. A user clicking "Code" gets the profile's repo list with no indication of which repo corresponds to the project. If these repos are private or don't exist yet, the link should be removed; if they exist under different names, the URLs need updating.
